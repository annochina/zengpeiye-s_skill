# 项目检查提问模板

以下模板保持原意使用，可根据当前项目名称、任务和阶段补充上下文。

## 任务开始前：需求明确性

```text
在我开始这项工作之前，请先帮我检查需求是否明确。列出：目标、输入、输出、验收标准、硬性约束、依赖项、潜在歧义和最容易返工的地方。如果信息不足，不要直接开始做，先指出缺失信息。
```

## 1. 拆解任务

```text
请把这个任务拆成若干可以独立验证的小步骤，优先安排风险最高、最容易出错的部分先验证。不要一开始就做完整方案。
```

## 2. 接口确认

```text
请帮我检查这个项目所有关键接口是否已经确定，包括硬件接口、软件接口、数据格式、尺寸、电压、电流、通信协议、输入输出关系和上下游依赖。指出哪些接口现在还不适合直接开工。
```

## 3. 开工前风险检查

```text
假设这个项目最后返工了，请反推最可能导致返工的10个原因，并告诉我现在可以提前做什么来避免。
```

## 4. 方案评审

```text
请以一个经验丰富的工程师视角审查我的方案。不要只判断能不能做，要重点寻找：遗漏、边界情况、接口冲突、错误假设、潜在兼容性问题和后期可能导致返工的设计。
```

## 5. 做到一半时

```text
当前任务已经完成一部分，请不要继续往下扩展，先检查现阶段结果是否满足原始需求，是否存在方向性错误，以及现在修改和以后修改的成本差异。
```

## 6. 交付前检查

```text
请对当前成果做一次交付前检查。按照“需求是否满足、功能是否正确、接口是否正确、异常情况、可维护性、兼容性、遗漏项、验收标准”逐项检查，并给出必须修改、建议修改、可以接受三类结论。
```

## 7. 硬件专用

```text
请对这个硬件设计做防返工检查，重点检查：供电、电压兼容、电流裕量、芯片引脚、接口方向、TX/RX、上拉下拉、去耦、电源时序、器件封装、器件方向、PCB线宽、安装孔、结构干涉、测试点、调试接口和可维修性。
```

## 8. 软件专用

```text
请对这个软件方案做防返工检查，重点检查：输入输出、数据类型、异常处理、边界条件、接口定义、配置项、版本兼容、依赖、日志、错误恢复、测试方法和后续扩展成本。
```

## 9. 复盘专用

```text
这次工作出现了返工。请不要只总结“以后细心一点”，而是分析根因，并把每一个问题转化成一个可以加入流程、模板、自动检查或checklist中的具体规则。
```
