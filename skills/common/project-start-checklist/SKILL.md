# 项目开始清单

## 目标

把项目要求变成可追踪、可验证的记录，尽早暴露信息缺口和高返工风险。这个 Skill 只负责开工前确认、阶段检查和复盘，不替用户擅自补齐未知需求。

## 每个项目的要求记录

项目专属要求存放在消费项目的 Git 仓库中：

```text
.agents/skills/<规范化项目名>/references/project-requirements.md
```

使用 [project-requirements-template.md](references/project-requirements-template.md) 创建或更新。开始任务前依次读取项目根目录的 `AGENTS.md`、项目 Skill、该要求记录、`README` 和相关配置；没有要求记录时，先报告缺失，不直接开始实现。不要猜测目标、接口、尺寸、单位、版本或验收标准；已确认的变更要在要求记录中留下日期、来源和决策。

## 默认开工门禁

任何需要修改代码、硬件、数据、配置或跨仓库接口的任务，开始实现前先输出：

- 目标
- 输入
- 输出
- 验收标准
- 硬性约束
- 依赖项
- 潜在歧义
- 最容易返工的地方

如果这些信息中有会影响方案或验收的缺口，停止在分析阶段，明确列出缺失信息并向用户确认。信息明确后，再按风险优先拆解任务，不一次性铺开完整方案。

## 按阶段执行

默认先做“需求明确性检查”。之后根据任务所处阶段选择对应检查：任务拆解、接口确认、开工前风险、方案评审、做到一半时、交付前检查、硬件专用、软件专用或复盘专用。硬件任务和软件任务可同时使用各自专用检查；不相关的检查不要为了形式强行执行。

每次检查都要区分：

- 必须修改：不处理就不能安全开工、验收或交付
- 建议修改：不阻塞当前阶段，但会增加后续成本或风险
- 可以接受：已核对、风险可接受或属于明确的非目标

## 标准提问模板

需要使用的完整中文提问模板保存在 [prompt-library.md](references/prompt-library.md)。其中第一条是所有实现任务的默认开工门禁；第 5 条用于阶段性停点，不能被用来继续扩展范围；第 9 条用于把返工根因转成流程、模板或自动检查规则。

## 输出和停止规则

1. 先给出当前已知事实、缺失信息、假设和阻塞项。
2. 高风险未知项优先验证，并把每个验证步骤写成可独立检查的小步骤。
3. 对接口给出名称、方向、类型、单位、范围、协议、版本、上游和下游；未确认项标记为“待确认”。
4. 未通过开工门禁时不写实现代码、不执行会改变外部状态的操作。
5. 任务中途或交付前发现方向性错误时，先停下报告影响和修改成本，再等待范围或方案确认。
6. 复盘时必须把每个根因转化为具体的 checklist、模板字段、自动校验或流程门禁。
